# ShopX Try On

## Android development build

The local Expo module autolinks from `modules/shopx-try-on`. It uses CameraX and MediaPipe Tasks Vision with the app's Expo SDK 51 and React Native 0.74 configuration. The config plugin raises the Android minimum to API 24 for MediaPipe. The native module runs on Android. Other platforms show an availability message.

```sh
npm ci
npx expo prebuild --platform android --no-install
npx expo run:android --device
```

Use an ARM64 Android device or emulator with both cameras to exercise switching. The bundled MediaPipe version does not include x86_64 native inference libraries. Android debug builds generated by Expo permit local HTTP. For the emulator, keep the product URL at `http://10.0.2.2:8000/api/products/`. For a physical Android device connected over USB, run `adb reverse tcp:8000 tcp:8000` and use `EXPO_PUBLIC_PRODUCTS_API_URL=http://127.0.0.1:8000/api/products/`. On Wi-Fi, use the Mac's LAN address and allow that host in development Django settings. Restart Metro after changing the environment.

The source images are from PNGImg and the derived overlays are for noncommercial local testing under the [CC BY-NC 4.0 license](https://pngimg.com/license). Commercial distribution needs appropriately licensed product overlays. The product picker uses the catalog image URL for each thumbnail. Per-item fit values live in `Geometry.kt`. Additional entries need a verified product ID, name, image match, and separate earring cutouts, a full wearable chain, or a transparent ring with an open band. Pendants eligible for the necklace mode need the full chain.

Face, pose lite, and hand MediaPipe model bundles are included in the Android assets. Preview and analysis share a native viewport. Analysis uses one worker, keeps the most recent frame and caps inference at approximately 15 FPS for bracelets and 11 FPS for the other modes. Frames are used in memory for inference. The React screen receives status transitions only.

### Bracelet model

Bracelets includes the supplied gold oval, silver filigree, and emerald vine gold models as local accessories. The silver and emerald models use simplified runtime meshes that retain the source material colors and separate details. The Android renderer reads the mesh directly. Hand world landmarks orient the bangle, while projected wrist and knuckle landmarks set the location and scale. The renderer clips the portion behind the estimated wrist and interpolates between tracking samples. The last valid wrist fit remains visible for up to 650 ms through brief detector gaps, then clears if tracking is still lost. Bracelet mode defaults to the rear camera and also supports the front camera.

## Physical device checks

- Try each item with its default camera and then switch cameras. Check that the overlay clears during each switch.
- Turn and tilt your head with earrings. Verify that each side fits independently and the far side disappears on larger turns.
- With the necklace, tilt and turn your shoulders, then cover one shoulder. Check that the pendant stays centered and the overlay clears when the fit is lost.
- Show the ring finger on both hands. Rotate and partially obscure the hand. Check that the rear band stays behind the finger and that the ring disappears when placement is unreliable.
- Try the bracelet on both wrists. Move side to side, bring the wrist closer, and roll from palm up to palm down. Check that the visible band stays on the wrist and that it disappears when the wrist leaves the frame.
- Walk out of view, leave and reopen the tab, and background the app. Check for stale overlays and confirm the camera indicator switches off when leaving.
